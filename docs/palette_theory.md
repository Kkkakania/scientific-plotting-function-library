# 调色板深层原理与硬约束

这套库的色彩科学工具跑下来揭示了一些非平凡的数学事实，
做配色时遇到"怎么也调不好"的死胡同，多半就是撞上这些约束。

## 三个核心维度的不可能三角

任何分类调色板都同时面对三个相互制约的目标：

1. **类别区分（正常视觉 ΔE 大）** —— 必须用色相、明度、彩度的差异
2. **色盲安全（CVD ΔE 大）** —— 必须避免红绿轴上的隔离
3. **灰度可读（L 通道两两差大）** —— 必须每个颜色的明度都不一样

**结论：色数 ≥ 6 时三者无法同时严格满足。**

证明草图：

- 设有 N 个类别要被同时区分。
- 灰度安全要求 N 个颜色在 L 轴上至少均匀分布；按经验 ΔL > 15 时安全，
  也就是 L 跨度至少 15·(N-1)，N=8 时为 105 —— **超出 CIE Lab 的 L 满量程 [0,100]**。
- 所以要么放弃灰度安全（多数顶级配色的选择，Wong/Okabe-Ito 均如此），
  要么把 N 限制在 ≤ 6 左右。
- 同时要色盲安全的话还得避开红绿色相轴，可选色相进一步减少。

## 验证：本库 68 套调色板的实测分布

| 颜色数 | 严格三安全的 | 至少双安全的 |
|---|---|---|
| 2 色 | `duo_warm_cool` | 大部分 |
| 4 色 | `bio_dna` 接近 | 多数 |
| 5 色 | `gray5`*（牺牲色相）| 部分 |
| 6 色 | （无）| 少数 |
| 7 色 | （无）| 一两套 |
| 8 色 | （无） | `wong` / `okabe_ito` 等 |

*`gray5` 是把"分类色"退化成纯灰度，所以三个维度自然全过——
但代价是色相维度被完全放弃。

## 实用决策树

```
你要画几个类别？
├── 2-3 个 → 选 `duo_warm_cool` / `duo_blue_red`，可同时三安全
├── 4 个   → `bio_dna` / `paper4`，三安全可达
├── 5-6 个 → `nature_soft` / `muted5`，放弃灰度，保 CB 安全
├── 7-8 个 → `wong` / `okabe_ito`，必然放弃灰度，至少做到 CB 安全
└── >8 个  → 改用分面（subplot）或多面板，别堆在一张图里
```

## 顺序色板没有这个问题

顺序色板（heatmap、密度图用）天然以单调 L 通道为轴：

- 灰度自动安全（L 单调 → 灰度也单调）
- 色相可以恒定（如 `blues`）或缓慢漂移（如 `turbo_like`）
- CB 安全只要不在 L 轴附近有色相突变即可

所以本库 14 套顺序色板里 11 套都能通过严格自验，远超分类。

## 发散色板的特殊性

发散色板（围绕中心正负偏离用）：

- L 通道必然在中心（白/浅）最大，向两端递减 → **L 不单调**
- 但人眼天然把它解读为"对称的两个轴"，所以 L 非单调是 *特征* 不是 *bug*
- CB 安全的关键：两端色相必须在 CVD 模拟下仍可区分（蓝-红组合在
  红绿色盲下崩，所以推荐 `purple_white_green` 或 `blue_white_orange`）

## 给你的实操建议

1. **3-4 个类别**：尽情选三安全的，没有妥协空间问题
2. **5-6 个类别**：从 `nature_soft` / `muted5` / `science_bold` 里挑，
   接受灰度不安全，但务必跑一次 `validate_report` 看 CB ΔE
3. **7-8 个类别**：默认 `wong`，做投稿前用 `palette_stress_test.png` 看一眼
4. **超过 8 个**：**结构性问题** —— 把图拆开

## 顺序色板调参口诀

用 `hcl_sequential` 或 `oklch_sequential` 时：

- `L_range = (95, 25)`：明度跨度 70 是甜蜜区
- `C_max = 70`（CIE Lab）/ `0.15`（OKLab）：太大蓝色域会被裁剪
- `hue = 60` 偏暖（橙黄）；`hue = 240` 偏冷（蓝紫）；`hue = 130` 绿色
- 单色相比多色相更稳，论文里推荐单色相

## OKLab vs CIE Lab

实测对比（同样 n=8、L=60、C=70）：

| 指标 | CIE Lab HCL | OKLab HCL |
|---|---|---|
| 正常 ΔE | 10.9 | 17.7 |
| 视觉均匀度 | 蓝紫色域略挤 | 全圈更均匀 |
| 数值稳定性 | 老牌 | 现代标准 |

**OKLab 在分类色板上显著更好**。除非有兼容性需求，新项目优先用
`oklch_qualitative` 而不是 `hcl_qualitative`。
