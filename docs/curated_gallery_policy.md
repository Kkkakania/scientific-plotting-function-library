# Curated Gallery Policy

这个仓库可以在本地生成很多图，但公开仓库不应该把所有 figure 都倒进去。
公开 gallery 的目标是让第一次打开仓库的人快速看到质量，而不是让他翻完全部渲染产物。

## 原则

- 公开仓库只放经过挑选的代表图。
- 全量渲染结果可以留在本机，用于 QA、对比和后续筛选。
- `gallery/matlab/`、`gallery/matlab_native/`、`gallery/dark/` 这类大批量输出默认不提交。
- 销售包、交付包、课程包、本地导出目录不进入 GitHub。
- 如果某张图要公开，必须能追溯到仓库里的公开源码、合成数据和渲染脚本。

## 什么图值得公开

优先公开这些图：

- 一眼能看出图型价值的图，例如 heatmap、Bode、surface、radar、forest、Sankey、spectrogram。
- 电气工程、信号处理、控制、机器学习、3D 科学可视化中辨识度高的图。
- 配色、线宽、留白、标题、图例都比较干净的图。
- 能代表某一类模板，而不是同一模式下重复换标题的图。
- 文件名清晰、没有本地路径、没有水印、没有个人信息、没有外部论文/平台痕迹的图。

暂时不要公开这些图：

- 批量重渲染出来、还没有人工筛选的图。
- 暗色模式测试图，除非它比亮色版更适合展示。
- MATLAB/Origin/Go 等工具链的中间输出。
- 销售包、打包目录或本地交付目录里的图片。
- 与已有公开图高度相似、只换了标题或随机种子的图。

## 推荐流程

1. 先在本地生成全量图。
2. 人工挑选 20-60 张最能代表质量的图。
3. 确认每张图都能由公开源码重新生成。
4. 把候选图列入 `docs/gallery_selection.md` 或 release checklist。
5. 只提交被选中的图和对应源码，不提交整个输出目录。

## 与申请材料的关系

公开申请材料应该引用：

- 仓库 README；
- release 页面；
- GitHub Actions；
- 验证报告；
- 少量精选 gallery 图；
- clean-room / provenance / curated-gallery 规则。

不要把本地全量图数量写成采用量，也不要把销售包或私有输出当作开源影响力证据。
